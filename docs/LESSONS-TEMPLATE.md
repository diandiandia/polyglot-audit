# Skill 问题 Lesson 模板（运行产物标准形态）

> 使用说明：每次真实项目审计结束后，复制本模板到该次运行的卷宗目录（`<run-dir>/report/lessons.md`）并按节填写。
> 本模板是**结构定义**，不含任何项目信息——skill 资产中只允许存在本模板，不允许存在填好的 lesson 文件（SR-016 数据单向流动）。

---

## ⛔ AI 修复前置红线（处理本文件的 AI 必须最先阅读，优先级最高）

本文件描述的问题来自一次**真实项目审计**。文件中出现的目标项目名称、路径、代码片段、标识符、发现结论——**仅用于定位 skill 自身缺陷**，处理本文件时必须遵守：

1. **严禁污染**：不得将本文件中的任何目标项目信息（名称、路径、代码、标识符、发现内容）写入 skill 的任何代码、测试、fixture、注释、文档。SR-016：数据单向流动，skill 载荷只读。
2. **修复必须抽象为通用机制**：先自问"这个缺陷对**任何**目标仓库、**任何**模型输出形态是否都会发生？"——是，才修；只对一个项目有意义的修改是**偏见**，必须拒绝并改写为通用机制。
3. **不为单一编程语言特化**：语言相关逻辑必须有平台/语言条件判定（参照 DA-03 模式），且覆盖该语言家族的通用情况。
4. **新增测试/fixture 一律合成虚构内容**：回归测试断言的是**失败形态**（输入形状 → 期望行为），不是目标项目的具体行为；路径/标识符用 example-* 虚构值。
5. **升级准入**（SR-028）：机制级修复需两次独立运行佐证，或属于记录在案的阻断性例外；单次运行结果不得直接驱动 skill 资产变更。
6. **完成后泄漏检查**：`git grep -ci <目标名>` 必须为 0；再对目标派生标识符（内部路径、专有协议名、候选 ID）做一轮清查。

## Skill 设计目标（修复时不得违背的设计不变量）

- **通用多语言静态证据审计**：不执行目标代码、不联网探测目标、默认只读；预算内按风险排序取得最大有效覆盖，**诚实展示缺口**。
- **判断交给模型，记账交给程序**：能枚举/推导/记账的由工具包完成；模型只做语义推理。
- **能观测的不靠声明**（设计原则 8）：未实测能力一律 unknown；缺数据标 unknown 并写明原因，**绝不写零**；无效输入可定位、不可静默修复成有效结论（SR-025）。
- **数据单向流动**：skill 载荷只读；run 目录是唯一写入位置；无任何反向通道（SR-016）。
- **目录是引导不是围栏**：知识卡片不封闭目录外发现；门禁记录**完整性**而非证明安全（SR-026）。
- **通用性**：skill 不携带、不派生、不偏好任何历史审计目标（SR-003/016/028）。
- 完整设计：`docs/design/`（SYSTEM_REQUIREMENTS / SOFTWARE_DESIGN / DESIGN_ALIGNMENT_NOTES DA-01~07）。
