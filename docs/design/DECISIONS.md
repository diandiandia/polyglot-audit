### 评审带来的设计调整

| 编号 | 事项 | 结论 | 理由与约束 |
|---|---|---|---|
| DR-011 | 会话内引擎与 MCP 适配 | 采纳。会话内协议标准化为“批量取任务、子 agent 自行提交”；M2 提供 `audit mcp`，只暴露四个工具 | MCP 让子 agent 可以被限定为只读工具，补上会话内引擎只读约束靠指令的短板。约束：MCP 工具说明会常驻宿主上下文，所以工具数固定为四个，建议只在审计时挂载。会话内引擎的用量来自宿主会话日志，读不到时标为不可得，不由 worker 自报 |
| DR-012 | 环境守卫基线 | 采纳。S1 按与框架无关的问题清单提取，注入提示包，不超过 300 token | 基线来自对目标的现场侦察，不是 skill 的知识，不违反 DR-006。约束：基线是需要核对的声明而不是豁免；每条带锚点并由程序校验；被用来放过多少处记入自审。评审估计它能压低三成以上的无效验证，这个数字未经度量，不写入目标值，由自审报告实测 |
| DR-013 | 跨单元断链补偿 | 采纳。hunter 产出悬空接收点（反向候选）与污点出口；验证前由程序按“符号 + 参数位置”对接；中间层按需排连接任务 | 局部数据流的判断交给模型，跨单元的拼接交给程序。约束：两种记录都有数量上限且只针对强信号；拼接结果只是待验证的候选；悬空接收点的验证开销不超过验证预留的 30%，避免重演“便宜地产生、昂贵地处理”。按需连接任务放在 M4 |
| DR-014 | 目录调整 | 采纳四条：基座语言同时加载（TypeScript→JavaScript，并推广到 Kotlin、Scala→Java 与 C++→C）；易泛化条目加安全限定并要求卡片写明“不算候选的情形”；C++ 的异步生命周期提到第 2 位；Shell 用“变量作用域、属性与名字引用污染”替换“下载即执行”，后者并入代码注入 | 条目排序目前没有数据支撑，最终由 150 格评测与留出评测校正 |
| DR-015 | 工具包实现约束 | 采纳三条：符号大纲用逐行启发式正则；schema 校验器手写最小实现；事件库启用 WAL 与忙等待超时，driver 下单写者 | schema 仍然是 JSON 文件而不是 dataclass，因为同一份文件要直接交给宿主 CLI 做结构化输出 |
| DR-016 | 预算变更 | 提示包上限由约 3,600 调到约 4,000 token（新增环境守卫基线 300、基座语言索引、输出契约加 50，运行简报减 100）；命令面保持 12 个，用 `mcp` 替换 `check`，校验并入 `submit --dry-run` | 按“突破预算需要显式决策”的规则登记 |
