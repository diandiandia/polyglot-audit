## 2. 已识别并在软件设计中处理的冲突

| 编号 | 问题 | 设计处理 | 尚需验证 |
|---|---|---|---|
| REV-01 | Git 提交/dirty 和非 Git 的 mtime、大小不能固定内容或排除同元数据变更。 | SD-03 使用内容摘要和私有冻结副本；采集前后检查并披露并发采集前提，不能确保时中止；原位漂移不替换当前 run。 | 底层快照语义、采集竞态和大规模存储成本。 |
| REV-02 | 旧设计无租约，in-session 超时重发可能接受过期提交，多写者仅靠 WAL 不够。 | SD-06 事务 claim、generation、期限、幂等与冲突处理；迟到结果拒绝，崩溃重建。 | SQLite 文件系统约束、故障注入及时钟异常。 |
| REV-03 | 并发任务实际花费未知时不能宣称聚合 token 硬上限。 | SD-07 原子预留可强制最坏限额，未知维度不放行硬模式；显式降级。 | 两宿主各项预算能否强制、调用嵌套和遥测完整性。 |
| REV-04 | 打开文件不能证明完整审读，清点分母与分块重叠会夸大覆盖。 | SD-08 按行区间并集区分上下文、工具读取和模型声明，缺日志为未知。 | 宿主日志的真实粒度与可靠性。 |
| REV-05 | 锚点顺序存在不能证明路径可达、守卫缺失或利用后果；静态确认可能过度。 | SD-05 要求独立语义验证并保留不确定性；机械校验只证明结构。 | 合成负例、真实留出集的误报及独立验证效果。 |
| REV-06 | 候选必须 source+sink 与悬空 sink 冲突，数组限额可能悄悄抹掉高风险。 | SD-04 分类型、分页或显式溢出与 incomplete，未连接半链不伪造确认。 | 高扇出下的分页可用性与成本；限额策略。 |
| REV-07 | 环境守卫基线会被误当豁免，注册锚点不能证明实际路径受保护。 | SD-04 记录范围/例外/未知，逐路径确认，缺证据不驳回。 | 多框架及条件注册的误报/漏报评测。 |
| REV-08 | 严重度允许调整而校验又强制等于规则值；条件字段又声称都必填。 | SD-05 保存规则与最终值，说明调整语义，按裁决条件校验字段。 | 调整权限、矩阵合理性与国际化呈现。 |
| REV-09 | MCP 四工具或只读提示不等于 OS 隔离，网络和任意其他宿主工具仍可能开放。 | SD-09 将 MCP 定位为传输；按写入、执行、网络分别探测并禁止静默降级。 | 两宿主配置加载、权限、攻击反例及 OS 隔离实际强度。 |
| REV-10 | 字典脱敏和允许列表不能证明导出中不存在项目关联或统计重识别。 | SD-11 默认不导出，有限类型白名单与人工审核，不通过即不导出。 | 低样本和聚合字段风险；审核流程可操作性。 |
| REV-11 | 工具上限、150 卡片、“30% 改善”及低成本目标没有可信实验支持。 | SD-02、SD-07、SD-10 将内容质量与数值目标作为待评测假设；不能以自动规则替代专业审查。 | 每语言资料审核、留出集与量化基准。 |
| REV-12 | SQLite 事务与文件落盘不是一个原子操作；存储损坏时承诺总能交付报告不成立。 | SD-06、SD-08 定义先发布文件、事务引用、恢复对账和不可写显式失败。 | 不同平台的原子重命名、fsync 和崩溃测试。 |

## 3. 尚未关闭的验证门禁

| 编号 | 门禁及关闭证据 | 不满足时 |
|---|---|---|
| GATE-01 | 明确受支持的 Claude/Codex 版本，并在真实宿主验证结构化结果、配置加载、委派、只读/执行/网络和认证。 | 该组合不标受支持；未知隔离需用户确认，禁止声称强制安全。 |
| GATE-02 | 用并发/崩溃/迟到提交及快照竞态夹具验证一致性，给出文件系统适用范围。 | 不得声称支持可靠恢复或并发运行。 |
| GATE-03 | 以宿主证据证明 token/费用最坏上限和用量完整性，或只发布明确的软预算/任务预算模式。 | 不得声称 token/费用硬预算。 |
| GATE-04 | 逐语言评审 150 类的公开依据、适用性和正反例，实际测量跨单元与留出语料。 | 名册保持草案；不得宣称 Top10 排名或大项目检出能力已验证。 |
| GATE-05 | 在规定机器、文件分布、预算及统计口径下测量性能、成本与覆盖；公布缺失数据。 | 数字仍是目标，未达到时报告并决定优化或修订目标。 |
| GATE-06 | 明确导出字段、敏感性、人工审核责任和失败关闭行为；以合成反例测试。 | 禁止跨运行自动导出或导入。 |
| GATE-07 | 选定受支持 Python 下限、JSON Schema 子集与 CLI/MCP 接口版本并通过兼容测试。 | 不公布未测版本为支持；不宣称完整标准兼容。 |

**审查结论**：SR-001～SR-030 均有设计落点；本轮发现的内部矛盾已在软件设计中给出处理方案。以上门禁尚未验证，因而本设计只能作为开发需求拆解及后续评审的输入，不能被称为“所有问题已解决”或“实现可发布”。
