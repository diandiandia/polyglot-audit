## 1. 里程碑与依赖

| 阶段 | 目的及进入/退出条件 |
|---|---|
| P0 探测与契约 | 开发能力探测、契约和测试方案；能力实测留到统一测试阶段。 |
| P1 确定性底座 | 实现快照、清点、契约、状态、预算和门禁及其测试代码。 |
| P2 静态审计闭环 | 开发 Recon、Hunt、Verify、报告、双引擎与三语言合成正反例。 |
| P3 知识与自审 | 逐语言编写和评审 150 个条目；开发自审与无历史目标信息治理。 |
| P4 测试与发布工具 | 开发大规模、留出语料、双 CLI、故障和成本测试工具；统一测试后再决定发布与支持范围。 |

依赖标记 `—` 表示无 SWR 前置；`SWR-xxx` 表示实现或经批准的稳定接口先行，不要求先完成测试验收。

## 3. 横切验收与发布约束

- 安全：满足 [GATE-01](./SOFTWARE_DESIGN_REVIEW.md#3-尚未关闭的验证门禁)、GATE-02、GATE-06；无法保证的组合不得发布为受强制隔离支持。
- 能力：关闭或明确限缩 GATE-03、GATE-04、GATE-07；卡片数量本身不构成发现质量验收。
- 成本与规模：按照 GATE-05 先确定测量口径和验收标准，再判断目标；不得为降低输出而隐瞒溢出、删减必要证据或不计未知。
- 数据：检测版本兼容、生成物与状态对账、用户语言及凭据保护；卷宗属于敏感本地数据，不进入 Skill 或测试资产。
- 完成定义：每个 SWR 有可复现测试结果及失败处理，需求/设计/开发追踪无遗漏；任何未关闭门禁均列入发布说明并限制相应承诺。
