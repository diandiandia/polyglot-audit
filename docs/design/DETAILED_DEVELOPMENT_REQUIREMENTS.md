# 详细软件开发需求与多人／多 Agent 派工

> 状态：可供评审和规划的细粒度需求草案，不代表实现、测试或用户授权已经发生。系统需求映射经 `DSR → SWR → SR` 追踪；见[原软件开发需求](./SOFTWARE_DEVELOPMENT_REQUIREMENTS.md)、[详细软件设计](./DETAILED_SOFTWARE_DESIGN.md)、[接口契约](./INTERFACE_CONTRACTS.md)和[设计审查](./SOFTWARE_DESIGN_REVIEW.md)。
>
> 下列条目是可分派的需求单元，编号 `DSR-001` 等均为需求编号。角色是**责任域而非必须的人数**；每项仅一名负责人合并，其他人可评审。按用户要求，**先完成全量开发，再统一进入测试**；P0～P4 是责任分组而非测试批次。测试用例可随开发编写，但不在全部开发完成前执行验收或把任何需求标为已验收。真实宿主和安全能力在测试前均为 unknown，不得宣称已支持。

## 1. 协作与共同完成标准

| 角色 | 责任及写入范围 |
|---|---|
| INT | 集成、用户入口、CLI、阶段组合；详细路径见 DDS-02。 |
| CON | 公共 schema、版本、校验、错误契约；任何跨团队格式由其维护。 |
| SNP | 快照、清点、信号、切块；只读目标代码。 |
| LED | 数据库、事务、事件、预算及恢复；统一持久状态。 |
| ANA | Recon/Hunt/Verify、packet、半链及定级。 |
| KNW | 语言知识及自审升级准入；语言子目录可分组并行。 |
| HST | Claude/Codex、in-session、MCP 能力验证与适配。 |
| RPT | 覆盖、报告、轨迹、成本及自审渲染。 |
| QAV | 安全、集成、规模和留出评测；独立于相应功能作者复核。 |

**全量开发完成定义**：所有 DSR 的生产实现、合成测试代码、夹具、运行文档及契约齐备并完成接口集成；不依赖真实目标或历史审计内容；不泄漏令牌；有可复核的变更和负责人；接口修改经 CON/INT 同意。随后统一执行测试并记录命令和结果，测试通过才算验收完成。表中的“测试／验证／通过”均指后续测试阶段的执行预期，而不是开发期前置门槛。依赖列指前置设计、契约或生产接口已经形成，不要求前置任务先测试通过；测试任务依赖全量开发完成。假接口可用于并行开发，但必须在全量开发完成前替换或仅作为测试替身保留。

### 1.1 共享资产与冲突控制

1. 每位开发者/agent 仅修改 DDS-02 自己的所有权目录；公共入口、schema、依赖清单及共享 fixture 由相应负责人合并。涉及别人的文件用契约变更请求，不并发覆盖。
2. 采用独立分支或隔离工作区；提交前同步约定的接口版本，跨域改动在集成前完成评审。不要使用真实审计结果填充 fixture 或提交调试日志。
3. 当统一测试发现宿主能力与设计冲突时提交变更：写明影响的 SR、DSR、接口、测试和门禁；禁止未经批准修改安全需求或用假实现通过发布测试。测试前所有能力视为 unknown，以保守默认实现，不得阻塞接口开发或伪称已验证。
4. 每个任务回执包含：DSR、修改文件、接口版本、测试命令与输出摘要、未完成项、交接人。阻塞用明确原因表示，不把“模拟通过”当“真实宿主通过”。
